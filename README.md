# LINEミニアプリ（会員証・スタンプ・ラリー・投票・受付・ID連携）

1つのミニアプリに次の5機能を入れています。

| タブ | 機能 |
|---|---|
| 会員証 | デジタル会員証（会員番号＋QR）／スタンプカード／特典 |
| ラリー | スポットのQRを読み取って集めるスタンプラリー |
| 投票 | 投票（回答後に途中結果を表示）・アンケート |
| 受付 | 整理券の発行・呼び出し（自動更新・任意でLINE通知）／来場予約 |
| ID連携 | 既存の会員番号とLINEアカウントの連携 |

スタッフ用の **管理画面（admin.html）** では、整理券の呼び出し、スタンプ付与・特典の使用（会員証QRをカメラで読み取り可）、集計、予約一覧の確認、ラリー用QRの印刷ができます。

## フォルダ構成

```
index.html         利用者画面（LINEミニアプリとして開くページ）
admin.html         管理画面（スタッフ用）
css/style.css
js/config.js       ★ LIFF ID と API の URL を設定
js/app.js          利用者画面の処理
js/admin.js        管理画面の処理
js/api.js          LIFFログイン・API呼び出し
js/ui.js           共通UI
js/mock-backend.js デモモード用（ブラウザ内で動く擬似サーバー）
shared/settings.js ★ 特典・ラリー・アンケート・予約枠などの設定
shared/core.js     業務ロジック（GAS とデモモードで共通）
gas/Code.gs        サーバー（Google Apps Script）
```

---

## 1. まずデモで試す（準備不要）

`index.html` をブラウザ（Edge / Chrome）で開くだけで、LINEログインなしの **デモモード** で全機能を試せます。

- 管理画面：同じブラウザで `admin.html` を開き、管理キー `admin` でログインします。利用者画面と管理画面は同じデータを共有するため、「整理券発行 → 管理画面で呼び出し → 利用者画面が自動で『呼び出し中』になる」流れも確認できます
- 別の利用者として試す：`index.html?user=2` のように開きます
- ID連携のデモ用会員：`100001` ／ `19900101`
- データを消す：ブラウザのサイトデータを削除します

## 2. 本番の準備

### (1) LINE Developers
1. [LINE Developers Console](https://developers.line.biz/console/) にログインし、**プロバイダー** を作成します
2. プロバイダーの中に **LINEミニアプリチャネル** を作成します
3. チャネルの設定で、次を確認・設定します
   - **エンドポイントURL**：後の手順(3)で公開する `index.html` の URL（https 必須）
   - **Scope**：`openid` と `profile` にチェック
   - **シェアターゲットピッカー**（友だちに紹介ボタン）：使う場合は ON
   - **Scan QR**（ラリーのQR読み取り）：設定項目があれば ON
4. 控えておく値
   - **LIFF ID**（例 `2001234567-AbCdEfGh`）→ `js/config.js` の `LIFF_ID` に設定
   - **チャネルID**（数字）→ GAS の `LINE_CHANNEL_ID` に設定

> 開発中のLIFF IDは、チャネルに権限がある開発者・テスターしか開けません。一般公開の方法（未認証ミニアプリ／認証済みミニアプリの審査）は、最新の公式ドキュメントを確認してください。

### (2) スプレッドシート＋GAS（サーバー）
1. Googleスプレッドシートを新規作成し、メニューの **拡張機能 → Apps Script** を開きます
2. 次の3ファイルを作成して、内容を貼り付けます
   - `Code.gs` ← `gas/Code.gs`
   - `settings.gs` ← `shared/settings.js`（**本番用に編集**。特にラリーの `code` は推測されにくい値に変更）
   - `core.gs` ← `shared/core.js`（そのまま）
3. **プロジェクトの設定** でタイムゾーンを「日本（東京）」にし、**スクリプト プロパティ** を追加します

   | プロパティ | 内容 |
   |---|---|
   | `LINE_CHANNEL_ID` | 手順(1)のチャネルID（必須） |
   | `ADMIN_KEY` | 管理画面のログインキー。20文字以上のランダムな文字列にしてください（必須） |
   | `LINE_MESSAGING_TOKEN` | 呼び出し時にLINEで通知する場合の、公式アカウント（Messaging API）のチャネルアクセストークン（任意） |

4. エディタで関数 `setup` を1回実行し、権限を承認します（データ用のシートが作られます）
5. **デプロイ → 新しいデプロイ → 種類「ウェブアプリ」**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
6. 発行された URL（`https://script.google.com/macros/s/.../exec`）を `js/config.js` の `API_URL` に設定します

> `settings.gs` や `core.gs` を変更したときは、「デプロイを管理 → 編集 → 新バージョン」で再デプロイが必要です。

### (3) Webに公開（https）
`line_miniapp` フォルダを、https で公開できる場所にアップロードします（例：Netlify のドラッグ＆ドロップ、GitHub Pages、Firebase Hosting など）。

- `gas/` フォルダはアップロード不要です
- `shared/settings.js` には本番用のラリーの `code` を書かないでください（公開サイトから見えてしまうため）。本番の値は GAS の `settings.gs` にだけ書きます
- 社外サービスの利用は、社内ルールに沿って確認してください

## 3. 運用

- **外部ID連携**：スプレッドシートの `ext_master` シートに `extId`（会員番号）、`key`（確認キー：生年月日8桁など）、`name`（氏名）を入力します
- **ラリーQR**：管理画面の「ラリーQR」タブで印刷します。QRには `https://miniapp.line.me/{LIFF ID}?rally=コード` が入っているので、LINEの通常のカメラで読み取っても、ミニアプリが開いて自動でスタンプが付きます
- **リッチメニューから特定タブを開く**：`https://miniapp.line.me/{LIFF ID}?tab=reception` のように指定します（タブ名：`card` / `rally` / `vote` / `reception` / `link`）
- **整理券の発行停止**：`settings.gs` の `ticket.open` を `false` にして再デプロイします。番号は日付ごとに1番から振り直されます
- **呼び出し通知**：`LINE_MESSAGING_TOKEN` を設定すると、呼び出し時に公式アカウントからメッセージが届きます。利用者がその公式アカウントを友だち追加していることと、ミニアプリチャネルと**同じプロバイダー**の公式アカウントであることが条件です
- **データの確認**：各シート（`users`、`tickets`、`reservations`、`answers` など）をそのまま見たり、書き出したりできます

## 4. 制限・注意

- GAS とスプレッドシートは、**小〜中規模（同時に数十人程度）** 向けの構成です。数百人以上が同時に使う大規模イベントでは、Firebase などのデータベースへの移行を検討してください
- 利用者は IDトークンを LINE の API で検証して識別しています。管理画面は `ADMIN_KEY` で保護しています。キーはスタッフ以外に共有しないでください
- 会員証のQRには会員番号だけが入っています（LINEのユーザーIDは含みません）
- アンケートなどで個人情報を集める場合は、プライバシーポリシーの用意と、利用目的の明示を行ってください
